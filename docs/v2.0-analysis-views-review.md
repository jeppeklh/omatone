# v2.0 Analysis Views Review

## Purpose

This note records the Phase 4 analysis-view slice that ships in `v2.0`.

It complements `docs/v2.0-implementation.md` by describing the chosen
UI surface and the review expectations for keeping diagnostics useful
without crowding the default tuner flow.

## Implemented Scope

Phase 4 currently ships one optional analysis card in `Tune`.

-   Default state: off
-   Enable surface: `Advanced` -> `Display` -> `Analysis views`
-   Live inputs: helper-owned `pitch` message diagnostics only

The card shows:

-   a bounded recent cents trace from the Rust helper;
-   helper-calculated spread across that visible trace;
-   current detector confidence when the active analysis hop produced one;
-   whether the visible pitch is live or being held by Rust-side
    stabilization while the helper waits for a cleaner confirming frame.

The card intentionally does not add a spectrum, waveform view, or
DAW-style timeline.

## Review Expectations

-   `Tune` remains unchanged when analysis views are disabled.
-   Quick tuning actions stay above the analysis card.
-   The chart is always paired with text so the view is still meaningful
    without relying on the visual trace alone.
-   No new motion is introduced beyond ordinary state updates; reduced
    motion therefore remains respected.
-   High-contrast mode keeps the same border and text emphasis pattern as
    the rest of the popup.

## Manual Review Checklist

-   Verify `Tune` with analysis disabled still reads as the `v1.5`
    baseline.
-   Verify the analysis card stays within the popup width on horizontal
    and vertical bar layouts.
-   Verify `no_signal` clears the trace and shows the placeholder copy.
-   Verify noisy or transitioning input can surface the held-lock copy.
