# Omatune v0.1 Verification

## Purpose

This document records the current verification workflow for the shipped
v0.1 scope.

Use it both as a release checklist and as the shortest path to confirm
that a later refactor still preserves the helper/UI contract.

## Automated Checks

Run from the repository root:

```bash
cargo fmt --check
cargo test
omarchy plugin validate /home/jklh/Projects/omatone
bash scripts/build-helper-release.sh
```

## Deterministic Helper Checks

These use Phase 6 helper test modes so failure paths can be verified
without physically unplugging devices.

### Startup Input Failure

```bash
OMATUNE_TEST_INPUT_MODE=unavailable OMATUNE_TEST_OUTPUT_MODE=ok cargo run --quiet --bin omatune-helper
```

Expected stdout:

```json
{"type":"error","code":"audio_input_unavailable","message":"simulated microphone input unavailable"}
```

`ready` must not appear before that error.

### Repeated Startup Cycle

```bash
for _ in 1 2 3; do
  bash -lc "sleep 0.10" | env OMATUNE_TEST_INPUT_MODE=no_signal OMATUNE_TEST_OUTPUT_MODE=ok cargo run --quiet --bin omatune-helper
done
```

Each run should emit:

```json
{"type":"ready"}
{"type":"no_signal"}
```

### Simulated Pitch

```bash
bash -lc "sleep 0.10" | env OMATUNE_TEST_INPUT_MODE=pitch:A4 OMATUNE_TEST_OUTPUT_MODE=ok cargo run --quiet --bin omatune-helper
```

Expected stdout starts with:

```json
{"type":"ready"}
{"type":"pitch","note":"A4","frequency_hz":440.0,"cents":0.0,"confidence":1.0}
```

### Output Failure On Tone Start

```bash
OMATUNE_TEST_INPUT_MODE=idle OMATUNE_TEST_OUTPUT_MODE=unavailable cargo run --quiet --bin omatune-helper <<< '{"type":"play_tone","note":"A4"}'
```

Expected stdout:

```json
{"type":"ready"}
{"type":"error","code":"audio_output_unavailable","message":"simulated audio output unavailable"}
```

### Runtime Input Disconnect

```bash
bash -lc "sleep 0.20" | env OMATUNE_TEST_INPUT_MODE=disconnect OMATUNE_TEST_OUTPUT_MODE=ok cargo run --quiet --bin omatune-helper
```

Expected stdout:

```json
{"type":"ready"}
{"type":"error","code":"audio_input_disconnected","message":"simulated microphone input disconnected"}
```

## Manual End-To-End Checklist

These checks still matter because they cover the actual Quickshell UI and
live host audio stack rather than only deterministic helper modes.

1. Enable or load the plugin in Omarchy.
2. Left click the widget to open the tuner popup.
3. Confirm the helper starts and the popup shows a listening or no-signal
   state instead of stale pitch.
4. Play a steady note into the microphone.
5. Confirm the note name, cents meter, frequency, and confidence update.
6. Confirm silence returns the UI to a no-signal state.
7. Click a guitar shortcut and confirm a reference tone starts.
8. Change the chromatic note and octave controls while the tone is
   playing and confirm the tone is replaced immediately.
9. Click `Stop tone` and confirm playback stops cleanly.
10. Force a recovery path by using the popup `Restart` control and
    confirm the widget returns to a ready or no-signal state.
11. Turn the tuner off and on again and confirm the widget remains usable.

## Current Hardening Notes

-   The helper now guarantees `ready` is written before any input-side
    `pitch` or `no_signal` message.
-   Microphone capture starts after `ready`; microphone open still happens
    before `ready`.
-   Reference output is opened lazily on the first `play_tone` request.
-   `scripts/run-helper.sh` now prefers `bin/omatune-helper` for a staged
    plugin-local release build before falling back to local build outputs
    or `cargo run`.
-   Consecutive duplicate `no_signal` messages are suppressed.
-   The widget exposes both off/on control and explicit restart for
    recovery after helper or device failures.
